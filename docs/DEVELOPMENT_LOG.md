### Issue 1: Resend Email Sending Failure

#### 1. Root Cause Diagnosis
1. **Invalid Sender Domain (`wishes@resend.dev`)**:
   - Both `.env`, `.env.example`, and `render.yaml` were previously configured with:  
     `RESEND_FROM_EMAIL=Wish Yours <wishes@resend.dev>`
   - Resend strictly prohibits sending from arbitrary subdomains or addresses on `resend.dev`. The **only** permissible sender address on their test domain is `onboarding@resend.dev`. Any other address triggers an HTTP 403 / 422 API error.
2. **Environment Variable Clobbering in `server.js`**:
   - The custom `loadEnv()` helper in `server.js` was parsing the local `.env` file and unconditionally overwriting `process.env[key] = value`, even when `value` was an empty string. On Render (or environments where keys are provided via the host dashboard), an empty local file could erase the live API key.
3. **Resend Free Sandbox Recipient Restriction**:
   - When sending from `onboarding@resend.dev` without a verified custom domain, Resend enforces a strict sandbox policy: **emails can only be delivered to the email address registered with that Resend account**.
   - Attempting to send to arbitrary third-party emails fails with an HTTP 403 error:  
     `You can only send testing emails to your own email address...`
4. **Missing Informative Server Diagnostics**:
   - Previously, failures returned generic 500 error messages without explaining why Resend rejected the dispatch or what action the developer needed to take in the Resend dashboard.

#### 2. Implementation & Fixes
- **`api/email.js`**:
  - Implemented `getValidResendSender(configuredFrom)`: auto-corrects any invalid sender on `resend.dev` to `Wish Yours <onboarding@resend.dev>`.
  - Implemented `maskEmail(email)`: masks recipient emails (e.g. `e***n@example.com`) to prevent leaking PII in server logs.
  - Added smart error diagnostics translating Resend HTTP 403 sandbox errors into actionable instructions directing users to verify their custom domain at `resend.com/domains`.
  - Added robust timeout (10s) and network error handling for native `https.request`.
  - Implemented transparent fallback simulation for development environments where `RESEND_API_KEY` is not yet configured.
- **`server.js`**:
  - Refactored `loadEnv()` to prioritize existing live environment variables, strip inline comments and quotes, and ignore empty string values.
- **`render.yaml` & `.env.example`**:
  - Updated `RESEND_FROM_EMAIL` to default to `Wish Yours <onboarding@resend.dev>`.
  - Documented the custom domain verification requirement.
- **`tests/test_resend_live.js`**:
  - Created a dedicated CLI diagnostic tool to verify Resend credentials and test delivery end-to-end.

### Issue 2: Fonts Not Displaying Correctly Across Application

#### 1. Root Cause Diagnosis
1. **Font Loading Architecture**:
   - Fonts were only declared via `@import url(...)` in `public/css/styles.css` without high-performance preconnect tags in the HTML `<head>`. This caused font swap delays (FOUT) and forced browsers to render fallback system fonts.
2. **Absence of User Selection in Creation Studio**:
   - `public/create.html` had no typography selector UI. Users could select occasion, relationship, style, and theme, but had no way to choose a font family.
3. **Hardcoded Font Classes on Greeting & Envelope Pages**:
   - In `public/wish.html` and `public/js/greeting.js`, `#greetingMessageBody` had a static class `font-serif-display` (`Playfair Display`), overriding whatever tone was desired.
   - The wax-sealed love letter module in `greeting.js` had hardcoded `font-serif-display` throughout the unfolded letter and memory quotes.
4. **Email Template Lacked Font Styling**:
   - Transactional emails generated by `api/email.js` did not inject Google Fonts links or dynamic font stacks into the email body, causing emails to render in standard system sans-serif.

#### 2. Implementation & Fixes
- **High-Performance Font CDN Loading**:
  - Added `<link rel="preconnect">` and Google Fonts `<link rel="stylesheet">` (loading `Playfair Display`, `Dancing Script`, `Great Vibes`, `Outfit`, `Pacifico`, and `Cinzel`) across all HTML files:
    - `public/index.html`
    - `public/create.html`
    - `public/wish.html`
    - `public/dashboard.html`
    - `public/admin.html`
- **Dedicated Typography CSS Classes**:
  - Added explicit utility classes with `!important` and fallback font stacks to `public/css/styles.css`:
    - `.font-playfair`
    - `.font-dancing`
    - `.font-great-vibes`
    - `.font-outfit`
    - `.font-pacifico`
    - `.font-cinzel`
- **Typography Selector in Creation Studio (`public/create.html`)**:
  - Added 6 interactive visual cards in Step 4 with sample font lettering.
  - Added a live font switcher dropdown in Step 6 above the editable message textarea.
- **Creator Controller Typography Management (`public/js/creator.js`)**:
  - Initialized `data.font_family = 'Playfair Display'`.
  - Added `setFontFamily(fontName)`: updates active button styles, updates active badges, updates the Step 6 dropdown, and dynamically applies the font to `#finalMessageInput` so users preview their font choice while typing.
  - Forwarded `font_family` in the wish publish payload and email sharing dispatch.
- **Interactive Greeting Page Typography (`public/js/greeting.js`)**:
  - Implemented `getFontStack()` and `getFontClass()` helpers.
  - Dynamically removed default classes and applied the wish's `font_family` class and inline font-family to `#greetingMessageBody` and `#personalMemoryText`.
  - Updated `openEnvelope()` to render the love letter text, memory excerpt, and sender signature in the selected font.
- **Email Template Typography (`api/email.js`)**:
  - Injected Google Fonts `<link>` into `generateEmailHTML()`.
  - Applied the selected font family stack to the email heading and greeting quote box.
- **Data Layer Sanitization (`api/wishes.js` & `data/db.js`)**:
  - Implemented `sanitizeFontFamily()` to validate against an allowed font whitelist (`Playfair Display`, `Dancing Script`, `Great Vibes`, `Outfit`, `Pacifico`, `Cinzel`) and safely fall back to `Playfair Display` on invalid input.
  - Updated `createWish()` and `updateWish()` to persist and sanitize `font_family`.
